01 / Analysis approach

Data preparation and accessibility method

The method links checked source data to reviewed pedestrian paths, then estimates residents and identifies schools within the modelled walking catchment.

  1. Check & cleanSite boundary, school records and Census population; duplicates, geometry and coordinates.
  2. Review the networkOSM walking paths, connectivity and access restrictions.
  3. Select access proxiesTwo distinct public-footway crossings on the northern site boundary: A and B.
  4. Calculate walking timeShortest paths from either origin at 4.8 km/h; clip paths at 5, 10 and 15 minutes.
  5. Represent the catchmentTravel-time contour with mapped water excluded from analytical land.
  6. Estimate & identifyCensus area-weighted residents and density; cleaned school points within the catchment.

Site access selection

A and B coincide with two distinct existing public footways crossing the northern site boundary. Both are retained so the analysis does not depend on a single speculative future entrance. Private/service contacts and paths merely running along the boundary were excluded.

The points are planning access proxies, not confirmed development entrances.

Network travel-time calculation

Multi-source Dijkstra selects the shortest travel time from either origin. Edge time is distance divided by 4.8 km/h (1.333 m/s); terminal edges are clipped to the time remaining.

Catchment representation

Network travel-time samples are interpolated with Delaunay triangles. Mapped water is removed from analytical land; display smoothing and bridge corridors remain separate from the population calculation. Metric calculations use British National Grid (EPSG:27700).

Data issues and corrections

Raw inputs are preserved. Corrections and exclusions are written to separate cleaned datasets, with record-level logs retained.

School coordinate checks using APIs

Each retained school was queried by name and address using the OS Places API to obtain British National Grid coordinates. Lower-confidence matches were checked using the Google Geocoding API. Google coordinates were adopted only when the returned postcode matched and the location passed the London bounds check; unresolved cases remain flagged for review.

The cleaned dataset retains the API-returned address, coordinate source, confidence and review status, so each location can be traced to its geocoding result.

Network and catchment validation

Network checks covered connectivity and pedestrian restrictions. Catchment checks covered mapped water and reachable-path coverage; comparison with an independent grid model tested consistency rather than observed walking behaviour.

The 10-minute walking catchment

Approximately {{AREA}} hectares of analytical land can be represented within the modelled 10-minute walk from access proxies A and B. The pedestrian network determines travel time; the shaded contour provides a continuous spatial representation, with mapped water excluded from analytical land.

Why use 10 minutes? Ten minutes is a practical local walking scenario for this early-stage workshop, balancing the immediate 5-minute neighbourhood with the broader 15-minute context. It is a planning choice rather than a prescribed standard or an optimised threshold; the two reference scenarios show how the result changes with the time allowance.

04 / Population

Population estimates and allocation sensitivity

The Census area-weighted baseline is transparent, reproducible and directly tied to the supplied Census totals. Land, building and floor-space weighting test the assumption that residents are evenly distributed within each census area. These are alternative spatial-allocation scenarios, not statistical confidence intervals.

For each LSOA: Census residents × area inside the analytical catchment ÷ original full LSOA area. Density is estimated residents divided by {{AREA}} hectares of analytical land.

Footprint weighting uses a building’s ground area, adjusted for residential use, without accounting for height. Floor-space weighting also uses recorded floor counts: two buildings with the same footprint can therefore receive different weights if one has more floors. The central scenario assumes 50% residential use for mixed-use buildings. Both methods redistribute the same Census totals; neither measures actual building occupancy.

05 / Limitations

Limitations

Access and school entrances

A and B are planning proxies rather than confirmed future development entrances. School address/location points are not necessarily pedestrian gates, so exact gate-to-gate walking times may differ.

Population timing and distribution

Census 2021 is not a present-day headcount. The baseline assumes uniform population within each LSOA; land, building and floor-space weighting test that assumption.

Network and walking conditions

Results depend on OSM completeness and fixed walking speed. Separately mapped footways are retained, but the model does not systematically represent pavements on both sides of every road as separate paths or resolve all crossing locations. This may affect crossing detours and walking times near catchment boundaries. Crossing delays, slope and individual mobility are not modelled.

Catchment representation

The contour is a derived representation of network travel time rather than an exact physical boundary. Validation checks agreement between models, not observed walking behaviour.
